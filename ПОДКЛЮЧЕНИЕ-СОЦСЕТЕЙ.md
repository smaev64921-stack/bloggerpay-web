# Подключение TikTok, YouTube и Instagram

Чтобы блогер мог подтвердить, что канал действительно его, площадка должна
сама сообщить нам, чей это аккаунт. Для этого нужны ключи — их выдают
бесплатно в кабинете разработчика. Регистрация делается один раз и только
вами лично: это ваша учётная запись и ваше приложение.

**Код уже готов и проверен** (23 автоматические проверки, `server/test-verify.mjs`).
От вас — вписать два ключа в `server/.env` и перезапустить сервер. Больше
ничего менять не нужно.

Пока ключей нет, приложение не врёт: кнопка «Подтвердить» честно говорит,
что проверка ещё не настроена, и ничего не ломается.

---

## Порядок важен: сначала домен, потом регистрация

При создании приложения обе площадки **сразу требуют адрес возврата** — тот,
куда вас вернёт после входа. Это адрес вашего сервера, и он должен уже
существовать по `https`. Если зарегистрировать приложение раньше, придётся
возвращаться и переделывать.

Правильный порядок:

1. **Поднять сервер на VPS с HTTPS-доменом** — раздел «3½. Боевой запуск»
   в `ВЫКЛАДКА.md`. Нужен домен вида `kassa.вашдомен.ru`.
2. Прописать этот адрес в `server/.env` → `PUBLIC_URL=`.
3. **Выложить приложение** (там же в `ВЫКЛАДКА.md`) — заодно станет доступна
   страница политики конфиденциальности, её спросит Google.
4. И только теперь — регистрация приложений по инструкции ниже.

## Чем заменить «ваш адрес»

Везде ниже `https://kassa.вашдомен.ru` — это адрес вашего сервера-кассы
(то же значение, что стоит в `PUBLIC_URL` в `server/.env`).

**Самое важное правило:** адрес возврата (Redirect URI) должен совпадать
с тем, что ждёт сервер, **побуквенно**. Лишний слеш в конце, `http` вместо
`https` или другой поддомен — и площадка откажет со словами «redirect_uri
mismatch». Копируйте строки отсюда целиком.

## TikTok

1. Откройте **developers.tiktok.com**, войдите своим TikTok-аккаунтом.
2. **Manage apps → Create an app.** Название — `BloggerPay`.
3. В приложении добавьте продукт **Login Kit**.
4. В **Redirect URI** вставьте ровно эту строку:

```
https://kassa.вашдомен.ru/api/verify/callback/tiktok
```

5. В доступах (**Scopes**) отметьте три:

```
user.info.basic
user.info.profile
user.info.stats
```

6. Скопируйте **Client key** и **Client secret** в `server/.env`:

```
TT_CLIENT_KEY=сюда client key
TT_CLIENT_SECRET=сюда client secret
```

7. Перезапустите сервер.

**Про проверку приложения (App review).** TikTok открывает доступ к данным
пользователей после ревью — это обычная процедура, как у Google. Пока ревью
не пройдено, вход работает только для аккаунтов, добавленных в приложение
как тестовые (в разделе с участниками). На ревью у вас спросят, зачем нужны
доступы — отвечайте по делу: «блогер подтверждает владение своим каналом,
мы показываем рекламодателю имя канала и число подписчиков; ничего не
публикуем от его имени и данные третьим лицам не передаём».

### Если TikTok показывает «Что-то пошло не так» и слово client_key

Эту страницу рисует сам TikTok, до нашего сервера дело не доходит. Значит
площадка не приняла ключ. Разбирать по порядку:

1. **Проверьте, что видит сервер.** Откройте админ-панель
   (`/admin`), раздел «Площадки». Кнопка
   **«Проверить»** заставит сервер сходить на площадку и сказать: заданы ли
   ключи, открываются ли адреса TikTok с этой машины, какие права
   запрашиваются и какой адрес возврата уходит.

2. **Ключ должен быть Client key.** В кабинете TikTok рядом лежат App ID,
   Client key и Client secret. Нужен средний. Скопирован он должен быть
   целиком, без кавычек и пробелов (лишние кавычки сервер срежет сам, но
   проверить стоит).

3. **Адрес возврата — побуквенно.** Возьмите его кнопкой «Скопировать
   адрес» в админ-панели и вставьте в кабинет TikTok. Требования площадки: только
   `https`, без параметров и без `#`, до 512 символов.

4. **Приложение должно быть одобрено (Live).** Пока идёт ревью, войти могут
   только аккаунты, добавленные в кабинете как тестовые
   (**App permissions → Test users**). Добавьте туда свой TikTok — тогда
   вход заработает у вас, ещё до одобрения.
   Важно: **любая правка настроек приложения возвращает его в Staging** —
   после каждого изменения подавайте на проверку заново.

5. **Права.** Без ревью TikTok выдаёт только `user.info.basic`. Если
   приложение просит больше, чем одобрено, вход упирается уже в права.
   Список задаётся настройкой, менять код не нужно:

```
TT_SCOPE=user.info.basic
```

   С таким набором мы узнаем имя и открытый идентификатор аккаунта, но не
   число подписчиков. Подписчиков даёт `user.info.stats` — его открывают
   после ревью.

### Если TikTok недоступен из России

Здесь две разные преграды, и путать их нельзя:

- **Браузер блогера** открывает страницу входа `www.tiktok.com`. Без VPN
  она не откроется, и это не лечится с нашей стороны.
- **Наш сервер** после входа сам меняет код на данные аккаунта — ходит на
  `open.tiktokapis.com`. Если хостинг туда не пускает, вход не заработает
  даже с верным ключом и одобренным приложением.

Второе решается адресом-посредником. Обе точки задаются настройками:

```
TT_API_BASE=https://ваш-прокси-для-open.tiktokapis.com
TT_AUTH_BASE=https://www.tiktok.com
```

Пусто — работаем напрямую, как раньше. Кнопка «Проверить» в админ-панели (раздел «Площадки») покажет,
открываются ли оба адреса именно с вашего сервера.

## YouTube

1. Откройте **console.cloud.google.com**, создайте проект (название любое).
2. **APIs & Services → Library** → включите **YouTube Data API v3**.
3. **APIs & Services → OAuth consent screen** → тип **External**, заполните
   название приложения, почту поддержки и вашу почту.
4. **Credentials → Create credentials → OAuth client ID**, тип
   **Web application**.
5. В **Authorized redirect URIs** вставьте ровно эту строку:

```
https://kassa.вашдомен.ru/api/verify/callback/youtube
```

6. Скопируйте **Client ID** и **Client secret** в `server/.env`:

```
YT_CLIENT_ID=сюда client id
YT_CLIENT_SECRET=сюда client secret
```

7. Перезапустите сервер.

Доступ запрашивается только на чтение (`youtube.readonly`) — приложение
видит имя канала, число подписчиков и открытые данные роликов, которые
блогер сам загружает в задания, и ничего не может изменить. Подтверждение
канала просит доступ `offline`: Google отдаёт ключ обновления, и сервер может
проверить ролик в момент зачёта, не прося человека войти заново. Пока
приложение в статусе Testing, войти смогут только почты, добавленные в
списке тестовых пользователей; для всех — нужна публикация приложения.

## Instagram

Instagram подключается входом Instagram (**Instagram API with Instagram
Login**) — Facebook-страница не нужна. Подходят **только профессиональные
аккаунты** (автор или бизнес): у личного Instagram не отдаёт статистику, и
приложение честно говорит об этом в окне «Подключить аккаунт».

1. Откройте **developers.facebook.com → My Apps → Create App**, тип
   приложения **Business**, название — `BloggerPay`.
2. **Add product → Instagram → API setup with Instagram login.**
3. В **Instagram business login → Business login settings** вставьте:

   **OAuth redirect URI** (тот же адрес, что у TikTok и YouTube, — после
   переезда это старый адрес из `OAUTH_BASE`):

```
https://kassa.вашдомен.ru/api/verify/callback/instagram
```

   **Deauthorize callback URL** и **Data deletion request URL** — сразу на
   адрес САЙТА (`PUBLIC_URL`, после переезда — московский; ретранслятор
   POST-запросы по старому адресу не пропускает):

```
https://адрес-сайта/api/verify/instagram/deauth
https://адрес-сайта/api/verify/instagram/delete
```

4. Там же возьмите **Instagram app ID** и **Instagram app secret** (не
   Facebook App ID!) и впишите в `server/.env`:

```
IG_CLIENT_ID=сюда instagram app id
IG_CLIENT_SECRET=сюда instagram app secret
```

5. Перезапустите сервер.

Доступы — два, оба только на чтение: `instagram_business_basic` (ник, имя,
картинка, подписчики, список публикаций — по нему сервер находит
загруженный Reels) и `instagram_business_manage_insights` (просмотры, лайки,
комментарии и репосты ролика — по ним начисляются деньги). Короткий доступ
сервер сразу меняет на долгий (60 дней) и продлевает сам, пока аккаунт
подключён.

Пока приложение в режиме разработки, подключиться могут только аккаунты из
**App roles → Roles → Instagram Testers**: тестер принимает приглашение в
самом Instagram (**Настройки → Приложения и сайты → Приглашения
тестировщиков**). Для всех — **App Review** обоих доступов (Advanced Access)
и проверка компании (Business verification). Пока ключей нет, в окне
«Подключить аккаунт» у Instagram стоит «Скоро».

Обратные вызовы Meta приходят, когда человек удалил BloggerPay в настройках
Instagram или попросил Meta удалить данные: сервер сверяет подпись
(`signed_request`, HMAC секретом приложения), удаляет аккаунт Instagram,
доступ к нему и снимает с подсчёта ролики, которые ещё ждут проверки. На
запрос удаления Meta получает номер подтверждения и ссылку на
`privacy.html#delete`.

### YouTube Shorts

Отдельных ключей не нужно — это тот же канал YouTube. В мастере задания
есть площадка «YouTube Shorts»: если выбрана она одна, обычное видео YouTube
в задание не загрузится. Shorts ли ролик, сервер узнаёт по странице
`youtube.com/shorts/<id>` (у Shorts она открывается, обычное видео уводит на
`/watch`); если страница недоступна — ролик подписывается Shorts, только
когда сама ссылка `/shorts/`, а задание «только Shorts» тогда пропускает
ролики до 3 минут.

## Что спросят на проверке — готовые ответы

Обе площадки проверяют приложение вручную и задают одни и те же вопросы.
Отвечайте коротко и по делу — ниже готовые формулировки, они соответствуют
тому, что сервис действительно делает.

**Название приложения:** `BloggerPay`

**Чем занимается приложение:**

> Биржа рекламы у блогеров. Рекламодатель находит блогера, деньги
> замораживаются на счёте сделки и переводятся исполнителю после
> выполнения работы. Блогеры подтверждают владение своими каналами,
> чтобы рекламодатель видел настоящие цифры, а не заявленные на словах.
> Есть и задания с оплатой за просмотры: блогер сам загружает в задание
> ссылку на свой рекламный ролик, а сервис проверяет, что ролик
> опубликован на его подтверждённом канале, и берёт открытые цифры ролика.

**Зачем нужны запрошенные доступы:**

> Доступ только на чтение. Он нужен для двух вещей: подтвердить, что канал
> принадлежит человеку, который его указал (название канала и число
> подписчиков показываются в профиле), и проверить ролики, которые блогер
> сам загружает в задания: что ролик опубликован на его канале и сколько у
> него просмотров, лайков и комментариев. Цифры ролика обновляются раз в
> сутки, пока ролик на проверке, и снимаются заново в момент зачёта — по ним
> считается выплата блогеру. Мы ничего не публикуем от имени пользователя,
> не читаем личные сообщения и не передаём эти данные третьим лицам.

**Что вы делаете с полученными данными:**

> Сохраняем идентификатор канала, название, ник, картинку, ссылку и число
> подписчиков, а по роликам, загруженным в задания, — название, обложку,
> длительность, дату публикации, просмотры, лайки и комментарии. Доступ
> (только чтение) и ключ его обновления хранятся на нашем сервере, никому не
> передаются и используются только для проверки этих роликов; при отвязке
> канала они удаляются, отозвать доступ можно и в настройках аккаунта Google.
> Сам ролик и его цифры видят рекламодатель задания и администрация сервиса.
> В лидерборде задания всем пользователям сервиса видны имя из профиля, ник
> и картинка канала, число роликов, их просмотры и заработок в этом задании —
> как на других площадках заданий; об этом сказано в политике.

**Ссылка на политику конфиденциальности** (её спрашивают обязательно):

```
https://адрес-вашего-сайта/privacy.html
```

Страница уже готова — файл `privacy.html` лежит рядом с приложением и
уезжает на хостинг вместе с ним. **Перед публикацией откройте её и
заполните два места**, помеченные синим: кто оператор данных (ИП или ООО с
ИНН) и адрес почты для обращений. Без этого проверку не пройти.

**Instagram (App Review у Meta) — по доступам:**

> `instagram_business_basic` — блогер подключает свой профессиональный
> аккаунт Instagram, чтобы подтвердить, что аккаунт его, и загружать в
> рекламные задания ссылки на свои Reels. Мы читаем ник, имя, картинку,
> число подписчиков и список публикаций — чтобы найти среди них ролик,
> который блогер сам загрузил в задание. Ничего не публикуем и не меняем.
>
> `instagram_business_manage_insights` — читаем просмотры, лайки, комментарии
> и репосты только тех Reels, которые блогер сам загрузил в задание: по
> просмотрам начисляется оплата за рекламу. Данные видят блогер,
> рекламодатель задания и администрация сервиса; третьим лицам не передаём.

**Демонстрация работы.** Часто просят видео или скриншоты, где видно, как
пользователь нажимает «Подтвердить», входит на площадке и получает отметку
в профиле. Снимите экран телефона на этом пути — минуты достаточно.

## Как проверить, что заработало

1. В приложении: **Профиль → Редактировать → Площадки → Подтвердить**.
2. Откроется окно площадки, вы входите и разрешаете доступ.
3. Страница возврата покажет **шестизначный код** и название вашего канала.
4. Возвращаетесь в приложение — оно само предложит ввести этот код.
5. Ввели — кнопка становится «Подтверждён», в карточке блогера появляется
   отметка.

**Зачем код, а не просто «готово».** Без него работала бы простая подмена:
злоумышленник берёт свою ссылку авторизации, присылает её блогеру
(«подтвердите канал, чтобы получить заказ»), тот входит в свой аккаунт — и
его канал записывается на злоумышленника, а настоящий владелец навсегда
получает «канал уже привязан». Код видит только тот, кто действительно
вошёл на площадке, поэтому подсунутая ссылка бесполезна.

Если что-то пошло не так, страница возврата объяснит причину человеческим
языком («ссылка не найдена», «слишком долго», «канал уже привязан»).

Проверить контур можно и до получения ключей:

```bash
node server/test-verify.mjs
```

## Если канал привязали не туда

Канал продали, аккаунт потеряли, подтвердили не с того профиля — отвязать
может оператор своим ключом:

```bash
curl -X POST https://kassa.вашдомен.ru/api/admin/verify/unlink \
  -H "X-Admin-Key: ВАШ_КЛЮЧ" -H "Content-Type: application/json" \
  -d '{"platform":"tiktok","externalId":"идентификатор_канала"}'
```

Идентификатор виден в базе (таблица `channels`) — после отвязки канал
сможет подтвердить любой аккаунт.

## Что уже сделано за вас (менять не нужно)

- Ссылка авторизации собирается по правилам обеих площадок (у TikTok ключ
  уходит как `client_key`, у Google — как `client_id`; доступы и адрес
  возврата подставляются сами).
- Метка проверки — случайная, одноразовая и живёт 15 минут; канал
  привязывается только по коду, введённому в приложении (см. выше).
- Код можно ввести не больше пяти раз — потом проверку надо начать заново.
- Один канал — один аккаунт: второй человек тот же канал не подтвердит.
- Доступ к площадке — только на чтение: даже с ним нельзя ничего
  опубликовать или изменить. Он хранится на сервере, чтобы проверять ролики,
  загруженные в задания, и удаляется при отвязке канала.
- Внутри Телеграма ссылка открывается через сам Телеграм, иначе окно бы
  не открылось.
- Instagram: долгий доступ продлевается сам; обратные вызовы Meta
  (деавторизация и удаление данных) проверяются подписью секретом
  приложения — подделать их нельзя.
- Набор проверок Instagram и Shorts — `node server/test-instagram.mjs`
  (поддельные Instagram и YouTube, настоящие не трогает).
